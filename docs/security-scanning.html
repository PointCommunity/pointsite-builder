PointSite Builder security scanning

All pull-request security stages are blocking. A staging URL is required before DAST is enabled.

Scan inventory

Stage Tool Gate
Local commit Gitleaks 8.28.0 Any detected credential blocks the commit.
Pull request and weekly npm audit High or critical advisories block.
Pull request and weekly TruffleHog 3.97.4 Verified and unknown credentials block.
Pull request and weekly Semgrep 1.176.1 Configured TypeScript, JavaScript, and OWASP findings block.
Staging candidate Runtime probes and DAST Enabled only after a private staging URL exists.

Triage

  1. Stop promotion and preserve the scanner output as private CI evidence.
  2. Confirm reachability and exploitability; do not suppress an unreviewed finding.
  3. Fix the source or dependency, add a regression test, and rerun every gate.
  4. Document a false positive narrowly with its evidence and an owner.

Credential response

Revoke and rotate a detected credential immediately, remove it from current and historical Git data where appropriate, audit its use, and store the replacement only in Cloudflare or GitHub secret storage. Never paste a live value into an issue, log, fixture, or report.

Database freshness

Scanners run on each pull request and every Monday. A newly disclosed advisory may appear between scheduled refreshes, so a candidate also reruns scans immediately before release.
