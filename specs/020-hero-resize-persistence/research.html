Issue 37 root-cause research

PM production finding

Phone, Tablet, and Desktop must own independent element geometry. Element identity, membership, ordering, and content remain shared. The current implementation violates that contract in two separate places.

  • Responsive grids store only desktop as required and resolve missing Tablet or Phone values through grid[breakpoint] ?? grid.desktop. A Desktop edit therefore changes an unmaterialized narrower view.
  • Hero headingWidth and bodyWidth are scalar numbers. The current viewport is not represented in the persisted value, so a resize necessarily changes all three views.
  • Placement alignment is also scalar even though the editor presents it alongside grid geometry, so it has the same coupling defect.

Observed architecture

  • HeroTextResizeHandle dispatches transient Puck replace actions during pointer movement and a history-recorded replacement on completion.
  • VisualEditor converts nextState.data into a cloned SiteDocument; transient actions call stageDocument and completed actions call completeDocument.
  • ActionAutosaveController snapshots each completed document, serializes requests, advances compare-and-swap checksums, and keeps newer local queue entries after older acknowledgements.
  • The schema, renderer, and existing tests accept optional integer headingWidth and bodyWidth values.

Responsive remediation decision

Version the document schema and require explicit desktop, tablet, and mobile values for grid area, placement alignment, and each Hero text width. Version 8 inputs clone their currently effective values into the three slots. New elements also begin with equal slots. CSS variables select the correct stored value at the same breakpoint thresholds already used by the canvas and public renderer. Removing inheritance also removes the inspector's “Reset to desktop” operation.

Confirmed root cause

The resize handle dispatched every pointer-move frame into Puck with recordHistory: false, and VisualEditor then staged each frame as editor document state. Its shared finish handler treated pointercancel as a completed action: it dispatched the starting width with history enabled and queued that restored value for durable autosave. A browser or overlay cancellation could therefore produce an immutable resize revision that restored the old width after the adjusted frame had appeared saved. The RED browser test also proved the cancellation created an extra save request.

Boundary evidence

  • A normal keyboard completion sent bodyWidth: 95 in the autosave request.
  • A normal pointer completion sent the same final width that the canvas rendered.
  • A cancelled pointer interaction sent an additional resize request even though it restored its starting geometry.
  • The schema and both repositories already preserve optional Hero width fields; they require explicit regression coverage, not a migration.
  • The current Hero schema supports left and center alignment only. The Issue's reference to right alignment is not an existing supported state, so this bug preserves and tests the two supported values rather than introducing a new alignment feature.

Decision

Keep drag frames visual-only by updating the rendered box style during movement. Dispatch one history-recorded Puck replacement on pointerup. On pointercancel, restore the original inline style and dispatch nothing. This makes the completed action the only document and autosave boundary. Keep an explicit cancellation callback for component unmount so panel and view transitions also remove document listeners, restore the durable style, and create no save.
