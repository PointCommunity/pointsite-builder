Friendly Workspaces — specification and delivery plan

Boundary: Builder and staging only. PointSite production is unchanged and production publication remains locked.

Navigation and publishing

  • Tabs are ordered Layout, Forms, Library, Preview, History, Settings, and administrator-only Admin.
  • There is no Publish tab. An authorized publisher uses Publish in Layout and receives an accessible modal that explains revision, staging base, verification, acceptance, and the production lock.
  • Viewers remain read-only and users without repository write access cannot publish.

Forms workspace

  • Create, duplicate, rename, delete, and select forms without technical terminology.
  • Configure recipient, subject, heading, introduction, submit label, privacy note, success guidance, density, and one- or two-column layout.
  • Add, duplicate, remove, and reorder fields; configure label, type, placeholder, help text, required state, width, and choice options.
  • Rendered forms retain native labels, grouped choices, instructions, browser validation, and status announcements.

Library and linked media

  • Show private uploads and media already attached to the draft; edit filename, display name, alternative text, and organizing tags.
  • Add validated HTTPS linked images, direct videos, and YouTube URLs to a draft-owned linked-media catalog.
  • An atomic Media element selects a linked-media item and renders an image, native controlled video, or allowlisted YouTube embed.
  • Unsafe schemes and unsupported YouTube URLs fail validation. Direct video never autoplays.

History and audit

  • Revision history is a compact list filterable by search and named/current status.
  • Audit actors resolve to GitHub usernames when known; actions, targets, and outcomes use plain-language labels with technical detail available secondarily.

Acceptance gates

  1. Schema v4 drafts migrate losslessly to v5 and existing routes retain production pixel parity.
  2. Unit and integration tests cover form configuration, linked-media URL handling, metadata persistence, history filters, modal behavior, and actor resolution.
  3. Cross-browser hands-on tests cover create/edit/reorder form, add linked media, place it in Layout, filter history, inspect audit, and stage-only publishing.
  4. Formatting, lint, typecheck, build, coverage, accessibility, security, performance, staging contract, and route parity all pass before completion.
