Implementation Plan

This plan implements the approved specification without deploying the Builder application.

Sequence

  1. Copy Versa Development into a private PointCommunity Project without copying cards.
  2. Rename and describe the Project for Builder, link the Builder repository, verify fields and views, and disable the copied merge → Done workflow that would close an Issue before production verification.
  3. Create the governed Builder label taxonomy; add and classify every open Issue with complete Project metadata.
  4. Update AGENTS, the shared policy, and eight Builder pipeline skills for Project-owned state transitions and direct production.
  5. Copy the five approved shared frontend skills and their provenance, then add regular-file Claude adapters.
  6. Update deterministic audits, tests, package commands, lint scope, and GitHub Quality.
  7. Run skill validation, focused script tests, full quality, performance, browser, and live read-only pipeline audits.
  8. Review the final diff and live GitHub readback; report remaining platform limitations.

Risks and controls

Risk Control
Copying Versa cards Copy without drafts or items, then verify the new Project begins empty.
Canary terminology leaks into Builder Alignment audit rejects Builder Canary/Staging release packages and checks the direct-production contract.
Project automation marks work complete too early Health checks require closed Issues for Done and the closure skill restores In Review if post-merge production fails.
Unknown local changes are overwritten Patch only relevant files and preserve the existing dirty worktree.
Unavailable branch rules are reported as active Record the GitHub plan limitation and make the pipeline audit report it explicitly.

Verification checkpoints

  • GitHub Project readback matches the exact approved schema.
  • Issue #18 readback matches P1, High, M and a valid governed state aligned with its live assignment.
  • All 13 canonical skills and 13 Claude adapters validate and align.
  • Repository source gates, performance, and browser tests pass.
  • The final pipeline-health audit has no errors and no state mutation.
