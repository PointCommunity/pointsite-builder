Spec 016 · data and state

Action autosave data model

Client queue entry

Field Rule
id Client UUID reused as the idempotency key for every retry.
document Immutable structured clone of the complete document at action completion.
category text-edit, control-change, add, remove, duplicate, reorder, move, resize, replace, undo, redo, or restore.
context page content, page details, page structure, forms, library attachment, linked media, navigation, theme, site settings, collections, section settings, element settings, element layout, revision history, or draft.
attempt Zero through three automatic retries; identity and order never change.

Revision extension

Column Type Validation
action_category TEXT nullable Null only for legacy rows; otherwise a server enum.
action_context TEXT nullable Null only for legacy rows; otherwise a server enum.

Both columns are immutable. Draft creation uses add/draft; revision restoration uses restore/revision history.

Queue transitions

editing → pending → saving → saved

saving → retrying → saving is bounded to three retries. Offline pauses at pending/offline. Conflict, validation, queue limit, and exhausted retry remain visible without removing the queue head.

Atomic persistence

A changed action inserts one revision, advances the draft pointer with compare-and-swap, appends one draft.save audit event with category/context/sequence, and stores the idempotent response in one D1 batch. A canonical checksum no-op returns the current draft without revision or audit insertion.

Rollback compatibility

Migration 0008 adds nullable columns and recreates the immutability trigger. The previous Worker ignores the columns, so application rollback remains safe. No existing record is rewritten or removed.
