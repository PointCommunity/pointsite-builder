Action-based autosave research

Confirmed current behavior

  • EditorProvider marks one whole document unsaved, waits five seconds, and saves the latest state.
  • A save response replaces the local document, so a newer edit made during the request can be overwritten by an older acknowledgement.
  • The global Save button invokes the same function; browser online events trigger the only automatic retry.
  • The API already supplies compare-and-swap, idempotency, canonical no-op checks, transactional D1 revision/pointer/audit writes, and immutable history.
  • All draft surfaces converge on updateDocument: Layout, page details and structure, Forms, Library attachments and linked media, Navigation, Theme, Site settings, and Collections.

Decision: explicit serialized queue

Each completed action becomes a queue entry with a stable UUID, immutable document snapshot, finite category, content-free context, and attempt count. One pump owns the authoritative checksum and sends only the head. An acknowledgement advances the server base but never replaces newer local state.

Saving every React update would create keystroke revisions; one trailing debounce would erase meaningful sequential actions; parallel saves would reorder compare-and-swap bases. All three alternatives were rejected.

Decision: content-free attribution

The browser sends enum values only. The server rejects unknown categories or contexts and stores the pair on the immutable revision and audit metadata. Edited values, dynamic titles, internal IDs, checksums, request IDs, documents, and media values never enter action metadata.

Decision: additive D1 migration

Add nullable action_category and action_context columns and recreate the revision immutability trigger. Legacy rows remain readable as null; new create/save/restore records populate both. No table rebuild or backfill is needed.

Cloudflare documents that D1 batches execute sequentially as a transaction and roll back the sequence on failure.

Accessibility decision

One persistent text-and-icon region announces logical saving, retry, and saved transitions—not keystrokes or pointer frames. Conflict, validation, queue-limit, and terminal failures use alert semantics without moving focus. This follows WCAG 2.2 SC 4.1.3 and W3C status-message guidance.
