Spec 016 · implementation plan

Action-based autosave

Technical context

TypeScript 5.9, React 19, Puck 0.23, Hono 4, Zod 4, Cloudflare Workers and D1, Vitest/Testing Library, Miniflare, and Playwright. Builder production is the only runtime; public PointSite and protected Staging remain untouched.

Architecture decisions

  1. Define shared action schemas and human-language mappings.
  2. Build a deterministic serialized queue with injected save and scheduling boundaries.
  3. Have the editor provider stage transient documents, coalesce text, close text on blur or another action, pump one request, preserve newer local state, and expose recovery commands.
  4. Adapt every surface with a static context; use Puck onAction and explicit grid intent for canvas actions.
  5. Extend revisions and the save contract with strict action metadata; update History and audit language.
  6. Measure request, write, storage, retry, and latency behavior; retain the 70% capacity warning.

Dependency order

contract and migration → queue RED/GREEN → provider RED/GREEN → surface adapters → history/audit → browser and capacity evidence → review and release

Verification strategy

  • Unit: boundaries, text coalescing, ordering, in-flight edits, retry, offline, conflict, validation, no-op, queue limit, undo, redo.
  • Integration: strict contract, additive migration, atomic revision/pointer/audit/idempotency, legacy rows, no-op, restore metadata.
  • Browser: every named workspace, rapid actions, absent global Save, status semantics, specialized Save controls unchanged.
  • Complete: repository checks, performance, security, all browsers, exact-head Quality, migration rehearsal, production health/assets, authenticated hands-on workflow.
