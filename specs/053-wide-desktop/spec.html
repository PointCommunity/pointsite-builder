Issue 53: Preserve authored Desktop composition

Objective and requirements

Keep the same saved page's authored 1280 CSS pixel Desktop composition when the viewport widens. Retain exactly Desktop, Tablet, and Mobile. Preserve heading wrapping, element widths, placement, alignment, spacing, hierarchy, and independent smaller layouts. Backgrounds and surrounding margins may expand. Existing drafts must not require reauthoring.

The Issue supplies the approved scope. Screenshot pixel dimensions do not establish CSS viewport dimensions, zoom, or device scale. Reproduction must measure loaded fonts and viewport geometry. No fourth breakpoint or forced no-wrap rule is authorized.

Research

Initial source inspection finds viewport-relative typography and spacing in src/site-kit/site.css, alongside capped content shells. The hypothesis is that text continues growing after its box stops growing. Full-width grid sizing and page Hero breakout rules also require measurement. Canvas and preview use the same site-kit renderer. Protected Staging vendors this renderer and compares exact Git blob identities.

CSS Values Level 4 defines viewport-relative units; its comparison functions permit bounding fluid sizing. Preserve relative text minima and ordinary wrapping for accessibility.

Measured cause and correction

The initial Chromium regression fails: the home introduction stays 790px wide while its font grows from 51.2px at 1280 to 57.6px at 1440; its height increases from 57.34375px to 129px as it wraps. The Hero text box stays 928px wide while its font grows from 70.4px to 79.2px, then 84px. Fonts were loaded and the document had zero horizontal overflow at all four measured widths.

Bound fluid typography and spacing to the authored 1280px viewport through one CSS length variable. Keep viewport units for full-bleed backgrounds and outer margins. Bound full-width authored grid/flow content and its grid-cell calculation to 1280px, centered in the wider section. Keep existing shell/narrow limits and smaller breakpoints. No renderer version or document migration is needed because the document format is unchanged; synchronize the changed CSS blob and retain exact compatibility checks.

Plan and verification tasks

Reproduced independently against the currently published Staging document: the Hero first wraps at 1338 CSS pixels (single-line at 1337), and the introduction first wraps at 1392 (single-line at 1391). Both fit at 1280 and wrap at 1440, 1920, and 2560, with unchanged text-box widths and no horizontal overflow. The Staging regression covers these measured boundaries using the unchanged published content.

Canvas parity testing also found that the editor wraps compatibility elements in a grid-item container. Its generic max-width rule overrides the introduction's 790px maximum, producing 1160px in the canvas while preview uses 790px. Restrict the grid-child constraint to actual grid sections so compatibility elements retain the shared renderer's own widths. Both iframe surfaces also retain the browser's default 8px body margins while Staging resets them. Reset the body margin when it contains the renderer so a 1280px canvas actually supplies 1280px to full-width content, matching the published page.
