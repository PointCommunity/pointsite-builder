Issue 39: Navigation surface colors

Research and scope

The shared site-kit stylesheet hardcodes dropdowns to canvas/text, while the root alone selects Primary. Transparent roots also override primary section text with the ordinary text role. Canvas, Preview and publication all use the same renderer; its publication contract pins the stylesheet blob. Fix these shared CSS rules without changing saved documents, destinations, structure, breakpoints, positioning, opening or dismissal behavior.

Color contract

Surface Root and closed toggle Open menu, dropdown and expanded toggle
Canvas canvas / text canvas / text
Primary primary / on-primary primary / on-primary
Transparent Transparent; inherit section text (on-primary in overlay sections) primary / on-primary, an opaque readable treatment over images and any section surface

Top-level and child links inherit their containing color pair. Hover, pressed and keyboard focus underline links without changing text contrast. Focus-visible uses a currentColor inset outline; expanded toggles retain their border and add an underline. Theme roles remain authoritative, including custom themes; arbitrary low-contrast user-selected theme pairs are not corrected by mixing unrelated colors.

Use the existing React, TypeScript, CSS and Playwright conventions and installed dependencies. Follow W3C contrast guidance and visible keyboard focus guidance. Retain semantic links, keyboard order, navigation and reflow.

Boundaries

Hands-on QA exposed existing grid clipping: focusing a child link scrolled hidden grid containers and displaced the root menu. Navigation-containing sections, grids and placements must allow visible overflow so dropdowns remain reachable. Preserve grid coordinates and clipping for other placements. Anchor the open responsive panel below its toggle without increasing the Navigation root height, so centered grid placements do not push the toggle upward. Browser checks verify stable toggle coordinates alongside the color contract.

No dependencies, schema migration, authentication or API changes. No public-site publication. Preserve unrelated work. All app tests and builds run locally. Evidence belongs in the existing Issue and PR; the source spec is the implementation contract.
