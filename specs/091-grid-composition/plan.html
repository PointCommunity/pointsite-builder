Issue #91 · Implementation plan

Plan for the approved specification and Issue acceptance criteria. This is a proposed architecture for review, not implementation evidence.

Decision and dependency order

  1. Inventory and parity baseline. Capture representative v9–v11 documents, every registered legacy variant, header/footer and screenshot layouts in tests. Separate authored content from hard-coded renderer styles. The baseline is the regression oracle.
  2. One shared composition contract. Add bounded nested groups and stable child IDs to the site document. A group arranges reusable semantic leaves on responsive grids: text, image, link/button, form, navigation, map/media and interactive/list content as needed for the full inventory. Reuse existing GridArea, breakpoints, media references, safe destinations and shared rendering. Keep logical order separate from visual layer order. Do not duplicate specialized Hero/Card/Contact renderers as new Point-only presets.
  3. Read-compatible baseline. Add versioned parsing/migration and composed rendering while legacy rendering remains unchanged. Keep new authoring disabled until a retained rollback image can parse and safely render the new contract. Keep the tested reader-capable Canary digest as the recovery image when the current Production digest cannot parse version 12. Exercise old documents and a composed fixture in a local native upgrade/rollback rehearsal.
  4. Authoring slices. First make a generic composed section editable using existing Puck slots and grid actions. Then add semantic text, independent media, image links and fit, forms, card/person composition, header/navigation/footer, and brand-neutral presets. Legacy variants remain readable and convert through Builder controls to equivalent editable content; they are no longer offered as Point-specific new-layout choices.
  5. Placement feedback. Use the same prospective element data and grid geometry for the translucent phantom and committed drop. Add root-page Image insertion that creates the future grid section at the intended location and selects its child. Keep invalid/cancel paths non-mutating.
  6. Parity and release. Shared site-kit output drives Layout, Preview and publication. Synchronize the reviewed renderer contract with its governed publication counterpart without initiating public publication. Full local QA and exact-head Quality precede Canary; each Production promotion requires PM testing and approval of its exact healthy Canary candidate. Production Showcase and Issue closure require verification and full Issue acceptance, not a second approval.

Risk controls

Risk Control
Strict v11 parser rejects new document nodes. Reader-capable recovery image before v12 writes; no bulk Production rewrite; record the prior Production digest and use the retained reader image if it cannot parse v12.
New grid geometry breaks legacy appearance or published parity. Keep legacy rendering path untouched until explicit conversion; golden route/viewport fixtures; compare same revision in Layout, Preview and generated output.
Intentional overlap clips content or changes reading order. Bound layer values and nesting depth; expose source-order controls; CSS grid with explicit overflow rules; keyboard/focus and 200% zoom checks.
Empty labels create inaccessible controls. Allow deletion in Properties; omit empty visual text, provide required nonvisual names or an actionable publish preflight for controls/linked images.
Palette drag preview differs from dropped output. Render a read-only clone of prospective data with shared renderer; derive preview and insertion from one intent; test pointer movement, viewport, invalid and cancellation.
Form/custom collection binding loses behavior. Retain existing form submission contract and stable source IDs; edit visual field placement separately; test validation and revision recovery.
Large feature destabilizes editor autosave. Small red/green slices; no Puck fork or new dependency unless existing APIs prove insufficient; verify action history, checkout and autosave after each checkpoint.

Boundaries and next gate

No database table migration is assumed: document JSON versioning is the current path. Reassess if source investigation disproves this. Do not change Issue body without approval, drop legacy support, silently disable accessibility checks, deploy an unreviewed tree, or publish public content. Break each slice into tasks touching at most five files, with explicit RED/GREEN tests and dependencies. The approved Issue and work selection authorize proceeding through these planning artifacts without a separate spec approval; unresolved material decisions still require PM direction.
