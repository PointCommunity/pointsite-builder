Exclusive draft checkout and editor restoration

Issue: #23. Objective: prevent concurrent draft mutation while preserving safe recovery across refreshes, reconnects, and devices.

Requirements

  • A server-authoritative lease belongs to one authenticated user and one active client. Acquisition is atomic; reacquisition by the owner rotates the client token and supersedes the older client.
  • The lease expires after 30 minutes without genuine activity. The UI warns at five minutes remaining. Polling, rendering, timers, and hidden tabs do not renew it.
  • Every document mutation revalidates actor, active-client token, draft status, and server-time expiry. Preview and viewer access never acquire a lease.
  • Connected foreground draft lists refresh availability within five seconds. Responses identify only available, owned by the caller, or held by another editor, plus an expiry time and a non-sensitive display label when safe.
  • All drafts waits for autosave settlement, persists safe view state, releases the lease, and returns to the list. Closing or losing connectivity does not release it.
  • Per-user state stores draft, panel, page, selected element identifier, preview viewport/zoom, and bounded pane scroll positions. Restoration clamps missing pages/elements and never restores dialogs, destructive actions, or unsynchronized content.
  • Acquisition, resume, transfer, release, expiry, denial, and forced read-only transitions are append-only audit events.

API success criteria

Operation Contract
GET /api/drafts/checkouts Content-free availability snapshot for all visible drafts.
POST /api/drafts/:id/checkout Atomic acquire/resume/transfer; returns a bounded opaque token and restored safe view state.
PATCH /api/drafts/:id/checkout Genuine activity and/or bounded view-state persistence; requires current token.
DELETE /api/drafts/:id/checkout Intentional release; current owner/client only; idempotent for a repeated release.
Draft mutations Require x-draft-checkout; stale, expired, transferred, revoked, archived, or deleted authority is rejected.

Commands and structure

Source: src/server/checkouts, repository contracts/implementations, draft routes, and client editor/list modules. Tests: Vitest unit/integration and Playwright E2E. Gates: npm run check, npm run test:performance, npm run test:e2e.

Boundaries

  • Always use server time, atomic D1 writes, bounded schemas, authorization, and accessible status/focus.
  • Schema migration must be additive and rollback-compatible with the prior Worker.
  • Never expose raw identity, tokens, content, IP addresses, or pending offline actions through availability or audit metadata.
  • Never change public PointSite content or introduce a Builder staging/canary environment.
