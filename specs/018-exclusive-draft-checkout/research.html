Exclusive checkout research

Existing evidence

  • D1 is authoritative; drafts already use immutable revisions, optimistic checksums, idempotency, roles, and append-only audit history.
  • Action autosave serializes acknowledged mutations and exposes whether navigation is safe.
  • App selection and editor panel/page state are currently mounted React state and disappear on reload.
  • Authenticated email is the stable internal actor identifier; availability must not disclose it.

Decision

Use one additive draft_checkouts row per draft and one editor_view_states row per actor. A random token is returned once and only its SHA-256 hash is stored. A conditional update/insert makes acquisition atomic. Same-owner acquisition rotates the token and client id. All comparisons use Worker-generated server time.

Alternatives rejected

  • Durable Objects add cost and operational surface unnecessary for the expected collaborator count.
  • Browser-only locks cannot protect direct API mutations or cross-device access.
  • WebSockets are unnecessary for a five-second SLA; foreground polling is predictable and fits free-plan capacity.
  • Releasing on unload destroys crash/reconnect recovery and unload requests are unreliable.

Capacity

At five-second foreground polling, ten simultaneous list clients consume about 7,200 requests and modest indexed reads per hour. Activity writes are throttled and piggyback on meaningful events. Both remain below documented repository planning ceilings for the expected small collaborator pool.
