Research and constraints

PointView validates the request Origin and consumes the nonce transactionally. Its Cloudflare Access session and active PointView account are prerequisites for the pilot.

Operations and rotation

Run npm run pointview:setup -- prepare with the approved --vault, verified --installation, and an unused --output path. This saves the generated private key directly into 1Password, reads it back, and writes only public source configuration. Register that configuration through PointView Owner administration. Validate and save there to prove the GitHub App repository, Project, and label mapping. Initial registration is disabled.

Run npm run pointview:setup -- stage with --vault, --item from preparation, and --registration pointing to the public configuration. It verifies the recovered key matches and stages it through Cloudflare secret stdin without printing it. It does not activate feedback. For the reviewed pilot release, configure POINTVIEW_MODE as pilot and POINTVIEW_ORIGIN as https://pointview-canary.eaglepass.io only after the source is enabled and VALID. Repeat candidate and live checks after secret or configuration changes.

For rotation, prepare with --previous pointing to the current public registration. This retains existing public keys while adding the replacement. Validate the expanded registration, stage the new key, verify a live handoff, and retire old public keys after outstanding assertions expire. Retain old vault items for recovery. To disable, run npm run pointview:setup -- disable and verify the action disappears within 30 seconds or on focus/refresh.

Production rollout requires PointView Production verification and source registration there. After verification, use production mode and https://pointview.eaglepass.io, verify every authenticated Builder role, and record the new released candidate. Secret changes create a Worker deployment and require fresh release identity and live verification.
