Architecture decisions

  1. Add a sanitized workflow snapshot assembled from the latest D1 job, current Staging head, and latest immutable approval.
  2. Keep lifecycle derivation as a pure shared client function with explicit, exhaustive phases.
  3. Strengthen publication with expected revision ID/checksum and stable client idempotency.
  4. Reuse the existing verification operation but suppress unchanged persistence/audit writes.
  5. Recheck Staging head inside the acceptance route; client state never unlocks the server gate.
  6. Use the existing protected site in a new review step; GitHub links remain supplementary.

Dependency order

contract → RED state/persistence tests → server recovery → UI progression/polling → browser proof → release

Risks and mitigations

Risk Mitigation
Polling consumes GitHub/API limits 10-second interval, mounted/pending only, 15-minute cap, manual fallback, no unchanged audit.
Old job restored for a changed draft Return candidate identity and derive a visible stale state; publish exact current revision only.
Staging changes after verification Compare head during snapshots and again server-side at acceptance.
Duplicate commits from refresh/retry Stable idempotency plus candidate reuse in the job store.
Screen-reader noise Announce phase changes, not every poll; show timestamps visually without live repetition.
Unrelated local work Continue in the isolated issue worktree and commit only task-owned paths.
