Requirements

  • Keep Builder direct Production at https://builder.pointatx.org. Routine product Issues retain exact candidate verification, rollback, post-deployment PM Testing and exact completion approval.
  • Framework adoption, updates and requested monitor management are direct maintenance, outside Issue creation and the active slot. They never deploy the application or create monitors by default.
  • Use Chris (brimdor), the available macOS arm64 host, and the full existing local suite. Preserve all Chromium, Firefox, WebKit and mobile browser coverage. Do not claim native Windows QA.
  • Keep branch protection disabled as recommended and currently configured. Local source/tree-bound QA and reviewed lightweight Actions remain mandatory.
  • Install canonical Pipeliner skills, provider adapters, config, validation and audit tools, reviewed CI and reconciliation ledgers, and exact upstream provenance.
  • Resolve all collisions semantically. Retain Builder-specific lifecycle authority and route Pipeliner product commands through those skills. General framework maintenance uses Pipeliner directly.

Full local QA is evidence, not a synthetic GitHub check.

Risks and recovery

Conflicting generic and Builder policies are prevented by explicit routing and regression checks. CI command hashes must be refreshed after reviewed dependency or workflow changes. Source-only adoption is recoverable with a normal reviewed revert; application and database state remain untouched. Task cleanup inventories generated files before setup and preserves existing resources. Single-environment Builder QA does not introduce an extra pre-production PM gate: product acceptance remains the existing Production Showcase.
