Issue 30: Rename a draft from inside the editor

Research and contract

The existing authenticated PATCH draft endpoint trims and validates names to 1–100 characters, enforces Editor or higher access, and records draft.rename. Both repositories modify name and updatedAt without changing identity or revisions. EditorProvider currently derives draft metadata from ActionAutosaveController; replacing a whole draft after renaming would discard pending document work. Autosave acknowledgements can also carry older metadata. Apply only confirmed name metadata and preserve it through subsequent save acknowledgements. The draft list reloads when the editor closes; publishing consumes the same editor context.

Use semantic buttons and a labeled input with explicit validation and separate status announcements, following WCAG 2.2 and WAI status-message guidance. Existing Builder themes, visible focus, button targets, and minimum editor width remain authoritative.

Interaction and scope

  • An active editable checkout exposes a visible Rename draft button and heading double-click. Viewer, archived, and unavailable checkouts expose no rename controls.
  • Entering rename mode selects the current name. Enter or Save name commits trimmed valid changed input; Escape or Cancel discards it. Blur leaves editing open to avoid accidental saves. Composition Enter must not submit.
  • Empty and overlong names show associated validation text. Unchanged values exit without a request. Saving prevents duplicate submissions and cancellation; failures preserve the original name and entered text for retry. Successful save and cancellation restore focus to Rename draft.
  • Rename status is separate from document autosave. Only name and the newer updatedAt are merged into controller metadata. Never replace document, revisions, queue, checksums, checkout, lifecycle, or publishing state from a rename response. Preserve confirmed names across stale autosave responses; explicit reload accepts authoritative metadata.
  • No dependencies, API, schema, role, publishing, or public-site changes. Existing draft.rename audit remains server-owned.
