Issue 28: Standardize the draft card action layout

Implement the selected Issue's approved scope within the existing Builder design system. Draft cards need predictable action placement at every supported width and text size. The Issue selection authorizes implementation and direct production release; final PM acceptance follows the production Showcase.

Research and diagnosis

DraftList.tsx places the primary action, checkout explanation, and every mutation in one shared button-row. app.css gives that row flex wrapping and space-between alignment. Different action counts and label lengths therefore produce inconsistent rows and gaps. Card headings and metadata also vary in height, so actions need a shared alignment model.

Use intrinsic wrapping with equal-width tracks; preserve DOM order rather than visually reordering controls. Reference: MDN CSS Grid, WCAG reflow, and WCAG text resizing. Verify 320 CSS-pixel reflow (the 400% zoom equivalent for a 1280-pixel viewport), and separately double text sizes without changing the viewport.

Layout contract

  1. Each card starts with its status, name, revision metadata and, when applicable, checkout explanation. Long text wraps inside the card.
  2. The action area follows the metadata. Cards in a row align the primary action even when their metadata heights differ. The primary Open editor, Resume editing, or Open preview control always spans the action area's full width.
  3. Editor, Publisher and Administrator cards place Duplicate then Archive or Unarchive on the following row in equal-width tracks. If the available width cannot support both labels, both become full-width rows in the same order. Viewer cards contain only Preview.
  4. Archived editable cards place Delete last on a full-width row with the existing danger styling. No invisible controls or arbitrary empty grid cells are introduced.
  5. Preserve the existing three/two/one-column card-grid breakpoints, theme tokens, button sizing, disabled checkout behavior, accessible names, and focus styles. Visual and keyboard order match; controls never overlap or clip at supported reflow and text sizes.

Enlarged-text reproduction also exposed draft-list heading/form overflow at tablet width. Allow this existing heading and New draft form to wrap within the panel and constrain the input to its available width. This is required for the Issue's no-horizontal-scroll criterion; creation behavior and other application forms remain unchanged.

Scope, files and style

Limit application edits to src/client/drafts/DraftList.tsx and scoped rules in src/client/app.css. Use semantic buttons, existing React/TypeScript conventions and Prettier; retain callbacks and the deletion dialog. Example class naming: className="draft-card__actions". Add component coverage in tests/unit/draft-list.test.tsx and focused browser coverage in tests/e2e/draft-card-actions.spec.ts. No dependencies, schema, lifecycle, publishing or permission changes are needed. Ask before expanding the approved Issue body or scope.
