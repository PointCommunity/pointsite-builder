Spec 017 · repository and live-system research

Why the canvas cannot yet be trusted

Confirmed renderer topology

The editor root injects the exact canonical site.css and renders through SiteFrame. Standalone preview uses an isolated iframe with the same CSS and SiteRenderer. Protected Staging keeps a copied 16-file site-kit. The remote Staging main observed on 2026-09-08 declares schema 8 / renderer 8.0.0 and all 16 Git blob IDs match Builder origin/main.

Root cause 1: collision fallback is presented as intent

SectionComponent calls resolveGridArea(pointed, fallback, occupied) and paints .area. On collision, that value is the fallback rather than the pointer target. Insert resolution repeats the same call and persists the fallback. The behavior is internally consistent but violates direct manipulation: the collision is invisible and the requested location is silently changed.

Root cause 2: semantic version does not prove parity

Candidate content and its manifest carry schema and renderer version, but Builder does not read Staging renderer files before writing. A stale or locally modified Staging renderer can share 8.0.0; failure is deferred to Staging CI after the candidate commit. GitHub content metadata exposes each file's Git blob SHA at an immutable commit, allowing a content-free exact contract check before writes.

Existing capabilities to preserve

  • New section variants already default to 12-column grid layout.
  • Existing documents retain compatibility/flow layouts and migration-generated grid coordinates.
  • Phone/tablet/desktop placement values persist in the SiteDocument and render through shared CSS variables.
  • Pointer transforms already account for iframe scaling and grid measurements; selected elements already offer keyboard movement/resizing and inspector inputs.
  • Authoring-only overlays exist only in the editing root.

Original 2026-09-08 decision

Keep the canonical site-kit unchanged in this Issue. Introduce authoring-only drop intent state and styles in the editor, reject invalid insertion by restoring the controlled Puck document, and add a server-side exact renderer preflight pinned to the expected Staging base SHA. This avoids touching the dirty local Staging checkout and makes publication fail before mutation.

2026-09-09 regression finding

Builder revision 227 exposed a desktop-only parity defect after an author moved the Navigation element away from its default auto-placement cells. The saved document places Navigation in columns 9–12 and the editing canvas honors those coordinates. Standalone Preview and the exact protected-Staging source instead render it beginning in column 5.

The non-editing renderer emits both responsive grid custom properties and a legacy .point-layout-item--span-N class. At desktop width, the later span rule overwrites the complete grid-column declaration, discarding its explicit starting line. Tablet and mobile declarations happen later inside media queries, which is why the defect can escape responsive checks and appear limited to desktop.

Regression decision

Grid sections must derive both start and span only from their responsive placement custom properties. Retain legacy span classes only for non-grid flow layout. Add browser geometry coverage that deliberately creates a gap before an item, then compares canvas and Preview at the same measured 1280 px viewport; retain explicit 768 px and 360 px containment checks. Synchronize the reviewed canonical site-kit to protected Staging before publishing a fresh exact revision.
