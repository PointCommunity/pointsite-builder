Research: draft and media independence

Specification · Source baseline e1a3330c1dadc596d585af7f15258d332266d5a6

Verified current behavior

  • repositories/d1.ts creates independent draft and revision rows, saves full JSON documents, and checks the revision checksum and checkout. Duplication currently copies document references without copying uploaded binaries.
  • media/service.ts lists uploads globally, caps that list at 100, and deduplicates on checksum/size across the system. media_assets has no draft owner. Metadata edits update a shared record.
  • MediaLibrary.tsx separately renders managed images, upload history, and linked media. “Use in Layout” attaches an upload to the document and switches panels; it does not place an image in a section.
  • setDraftStatus only changes the status and deletion timestamp. Content remains in revisions and idempotent responses. The existing retention policy waits 30 days and requires a saved export.
  • publish/candidate.ts copies uploaded binary bytes into Git candidate files but inherits other local assets from the destination repository. Candidate checksums include the bytes that are explicitly copied. GitHubStagingClient.commitFiles creates a commit on the existing Staging tree.
  • RetentionService currently derives media references from latest nondeleted drafts, missing retained historical references. Its deletion order removes bytes before the database batch. It must not remain an alternate unsafe deletion route after ownership changes.
  • Immutable revisions, preflight foreign keys, publication jobs, approval records, editor state, and idempotency caches all participate in the ownership/purge design. A row disappearing from the Drafts page is insufficient proof of deletion.

Technical sources

  • Cloudflare D1 database API: use transactional batches for metadata, version bindings, private chunks, and audit operations; an error must roll back the entire operation.
  • Cloudflare D1 limits: keep queries within parameter and statement limits. Use bound parameters, bounded batches, and complete pagination; do not build an unbounded list of IDs into one query.
  • W3C modal dialog pattern: explicit labeling, focus containment, dismissal, and focus restoration govern destructive confirmations.
  • W3C native dialog technique: prefer native dialog behavior when compatible with the existing test and UI stack.

Decisions

  • Use explicit per-draft ownership and immutable binary versions. Preserve a Library item's logical identity independently of the stored binary version.
  • Keep each existing revision's document and checksum intact. Migration binds its referenced asset paths to owned immutable copies; only a new revision may update current content paths.
  • Do not use global upload deduplication to connect drafts. A duplicate operation creates independent ownership and copies the required bytes.
  • Published files are destination-owned snapshots. Their existence does not retain the source draft. External linked services remain external; publication copies the link and accessibility metadata.
  • Use server-derived usage and deletion blockers. Search and sorting operate on the complete inventory for one draft, with no cross-draft details in UI messages.
  • Disable legacy orphan cleanup for newly owned assets; all cleanup paths must use the same ownership and reference rules.
