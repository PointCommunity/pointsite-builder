Implementation plan

Specification · Verification checklist

  1. Prove existing isolation gaps. Reproduce stale private data after deletion in both D1 and memory repositories. Add cross-draft media and independent-publication checks before changing behavior.
  2. Define and migrate ownership. Introduce per-draft Library and immutable binary ownership, complete reference checks, safe timestamps, and idempotency tombstones. Keep retained documents and published evidence intact. Prove atomic rollback and recovery compatibility before enabling mutations.
  3. Create and duplicate complete drafts. Copy all required local bytes into the new draft's ownership. Enforce owner checks on saves and media reads. Archive freezes the entire workspace; unarchive restores the same content.
  4. Publish independent snapshots. Package every required local asset, validate paths and checksums, and make the completed snapshot independent of source-draft survival. Coordinate publication and purge with server leases. Use synthetic destinations to test Staging and Production ownership semantics without publishing the public Production site. Read candidate images in bounded bulk queries. Upload Git blobs in resumable steps within the free Worker request budget; revalidate the exact draft, candidate, lease, and destination before each step. Update the destination branch only when the complete snapshot is ready.
  5. Purge an archived draft. Delete its complete private ownership graph transactionally, including history, binary chunks, preflight payloads, editor state, and cached responses. Retain only content-free receipts. Prove no resurrection and no effect on other owners.
  6. Deliver the unified Library. Replace the three inventories with one mixed-media list. Connect uploads, timestamps, filtering, sorting, counts, archive navigation, and unarchive to the scoped server API. Preserve the installed design system and existing editor selection controls.
  7. Deliver safe image replacement and item deletion. Add preview and final confirmation, fresh alternative text, server validation, atomic update, blockers, cancellation, keyboard operation, and focus restoration.
  8. Verify and release. Run all configured local suites and cleanup, review the exact diff, complete lightweight GitHub checks, merge and deploy the exact Builder candidate, verify live affected behavior, and present the PM Showcase. Keep Issue #32 open until PM acceptance.

Coordination

Schema, shared contracts, ownership migration, and publication/purge ordering are sequential. Independent reproduction tests may run in parallel. UI work may run in parallel only after its API contract is fixed. No unreviewed intermediate database or UI slice is deployed.

Risks addressed first

  • Historical references and a global media uniqueness constraint make simple owner-column addition insufficient.
  • Creating a candidate against a base Git tree does not prove that every image belongs to the candidate; validate complete asset closure explicitly.
  • Purging only visible draft rows leaves private content in revisions, operation caches, or binary chunks. Test each storage location.
  • Old workers and maintenance scripts can bypass new ownership. Verify compatibility and disable unsafe legacy paths before exposing destructive controls.
  • Copying shared images increases storage use. Capacity checks must count the actual private copies and fail atomically.
